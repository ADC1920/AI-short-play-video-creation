# 技能更新说明 · 2026-10（参考四个开源项目）

> 整理 2026-10-15 ｜ 资料来源为各项目的 GitHub 仓库与官方文档 ｜ 用途：v1.10.0 更新的来源记录，内容已于当日全部实施 ｜ 第一轮参考记录在开发机档案中（对应 v1.8.0 / v1.9.0）

## 0. 概览

四个项目都做 AI 视频生产，形态差别很大。OpenMontage 是全流程制作平台，HyperFrames 是代码渲染引擎，Hypit 是爆款复刻工作流，Brag 是宣传片生成 skill。本次只吸收它们的做法和思路，没有搬任何架构。共记 6 个更新点，落在 3 个文件里，技能内容没有新增文件（本文档除外）。

## 1. OpenMontage（calesthio/OpenMontage）

- 定位：agent 优先的端到端视频制作系统（12 条流水线、100+ 工具、700+ 指令文件）。没有代码编排器，AI 编程助手就是控制平面；创意决策与审查标准都写在 Markdown 和 YAML 里。
- 核心机制（实查摘录）：
  - 流水线：research → proposal → script → scene_plan → assets → edit → compose → publish，每阶段一个 director 指令文件，产出可机检的中间件
  - 合成前验证：交付承诺检查（标称「运动为主」却静图占比 80% 会被拦截）、PPT 风险评分、渲染器治理
  - 渲染后自审：ffprobe 验证、4 处抽帧查黑帧与破损、音频电平查静音与削峰、承诺核对、字幕检查，不过审不交付
  - 源文件探查：处理用户素材前先探分辨率、编解码、音频通道、时长，不凭文件名猜内容
  - 参考视频驱动：粘一条参考视频，分析文案、节奏、场景、关键帧、风格，给出 2-3 个差异化概念和成本估算
  - 预算治理：估算、锁定、结算三步，支持只记录或硬上限两种模式
- 与本技能对照：本技能已有相应的做法，包括视觉验收纪律、先图后视频与重生预算、素材形态逐款核对（教训 L-10）、多会话档案（agent-log / continuity-log 承担断点记录）。
- 本次吸收（理念级）：
  - [A] 对标参考流程（与 Hypit 合并，见 §3）
  - [C] 成片机检三查（ffprobe 对账 / 抽帧查黑帧 / 音频电平）→ 落 `references/transition-editing.md`
  - [E] 预算轻量账（估算 → 批量前确认 → 生成后记实际）→ 强化 `SKILL.md` 成本纪律既有条目
  - [C+] 交付承诺自查：「本片不能是静图轮播 / PPT 感」类承诺在分镜期与交付期各核一次。**实施时未采纳**，关联弱：本技能产物为生成视频，不存在 OpenMontage 式「标称运动、实际静图占比高」的典型风险；其精神已由视觉验收纪律覆盖。
- 未采用：流水线 YAML、断点体系、7 维评分选型、多提供商容错架构。这些是「全流程平台」的骨架，本技能是单路线的工艺技能，搬过来只会变重；它们的核心诉求（阶段检查、可恢复、决策留痕）本技能已有低成本对应。

## 2. HyperFrames（heygen-com/hyperframes）

- 定位：HeyGen 开源。用 HTML/CSS/JS（GSAP、CSS 动画、Lottie、Three.js）写画面，在无头浏览器里逐帧渲染成确定性 MP4。Apache 2.0 许可，附 CLI（init / preview / render / lint / capture / beats / tts / transcribe）和组件库，支持用变量做参数化批量。
- 与本技能对照：本技能主体是 AI 生成（Seedance），HyperFrames 是代码渲染（文字动效、图表、数据可视化），两边互补。本项目后期走剪映，代码渲染路线暂时用不到。
- 本次吸收（工具指针）：
  - [F] 后期工具路线对照补一行（`transition-editing.md` 第十节）：代码渲染路线适合什么（文字动效、图表、片头包装、批量参数化变体、官网转视频）、不适合什么（实拍内容、复杂表演）、引入成本（Node.js 22+ 环境）
- 未采用：CLI、Studio、组件库的整体引入，依赖较重，等有实际需要再评估；它的节拍检测（beats）与 audio-voice 的 BGM 卡点思路相近，先留指针。

## 3. Hypit（hypit-ai/hypit）

- 定位：用 AI agent 把爆款视频复刻成可编辑、可重跑的工作流（画面、字幕、B-roll、特效）。核心做法是把元素锚定在词上而不是秒上。一条命令可出 100 个变体，也支持不调用生成模型、纯代码渲染出片。
- 本次吸收（理念级）：
  - [A] 对标复刻纪律（与 OpenMontage 参考驱动合并）：拆解维度（结构、节奏、钩子、字幕样式、素材穿插）→「保留 / 更换」两栏清单 → 差异化方案；红线是学结构不抄内容、不承诺逐帧复刻、不使用无权素材
  - [B] 词锚定迭代原则：改词或多语言迭代时保持词序骨架、只替换词内容，时间轴按语速折算重新流动，不必手动重排秒表 → 落 `references/prompt-craft.md` 时间粒度节
- 未采用：100 变体批量引擎与词对齐运行时，它们依赖 Hypit 自己的运行环境，不是文档能承载的东西；「复刻范围可指定」（只借字幕样式、开场结构、素材穿插方式）已并入 A 的维度拆解。

## 4. Brag（latent-spaces/brag）

- 定位：Claude Code skill。读项目代码，规划产品故事（2 秒钩子、至少一处真实物料、每行字留足阅读时间、全片 15-25 秒），交给 HyperFrames 渲染，再校验并写分享文案。故事与渲染的职责边界划得很清楚。海报帧从成片里挑最佳帧，并烘为第 0 帧作缩略图。
- 本次吸收（局部工艺）：
  - [D] 发布包装：封面帧判据（画面完整、主体清晰、能代表内容）+ 烘第 0 帧 + 分享文案要具体、忌套话 → 落 `SKILL.md` 交付纪律附近
- 未采用：插件分发机制与捆绑音乐资产，与知识技能的定位无关。
