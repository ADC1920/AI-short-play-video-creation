# 衔接与后期（转场决策 · 编辑 · 延长）

> 何时读：规划转场、修改已有视频、把片段接长或接续时。

## 一、转场决策：该剪辑做还是模型做

一次生成要花钱，而且控制力不如时间线。两个决定按顺序：

**决定一：这个转场该由模型生成吗？**

| 转场 | 该在哪做 | 为什么 |
|---|---|---|
| 硬切 | 剪辑 | 没有东西需要生成 |
| 淡入淡出黑/白 | 剪辑 | 精确、可调、免费 |
| 叠化 | 剪辑 | 同上，时间点更好控 |
| 闪白/闪黑 | 剪辑 | 那里帧精确，模型只是近似 |
| 擦除/推移 | 剪辑 | 几何效果，不是被拍下来的事件 |

值得**生成**的转场，是剪辑无法从两条成片里凭空造出来的「被拍摄的事件」：

| 转场 | 是什么 | 适合 |
|---|---|---|
| 遮罩 | 镜头前进直到某物体填满画面，下一镜从中拉出 | 空间与时间跳跃 |
| 相似物 | 前一镜末帧的形状/轮廓/颜色变成下一镜首帧 | 蒙太奇、概念连接 |
| 动作/甩镜 | 快速运镜糊掉，在下一场景中解析出来 | 速度、动作、旅行 |
| 动态接力 | 主体动作跨镜延续：从一侧出画，在下一镜入画 | 换装、地点跳跃 |
| 推拉穿越 | 一个细节被放大成下一场景，或反过来 | 尺度切换 |
| 材质蔓延 | 墨、烟、光铺满画面，下一场景从中浮现 | 风格化作品 |

**决定二：在切点写明类型。** 骨架一行：`在切点使用<转场类型>。`
需要调度的写清机制：**触发动作 → 运镜 → 视觉变形 → 到达状态**。「到达状态」最常被省略，而它正是防止转场完成后新镜头继续漂的东西。
```
在切点使用遮罩转场。摄影机向前推进，直到一个人的背影填满画面、画面转暗；
下一镜从黑暗中拉出，露出展厅内部。
```

## 二、「禁止硬切」的正确作用域

`禁止硬切` 和 `禁止物体凭空出现` 是**延长与续写的默认值**——在那个场景里它们是对的。在别处，硬切和凭空出现是**手法**（闪现、跳惊、魔法显形、喜剧节奏）。全局挂上等于删工具。

- 延长/接龙连续动作 → 开
- 刻意制造不连续 → 关
- 其余 → 每片一决定

通则：**一个作用域里正确的默认值，不是全局规则。**

## 三、受限菜单法（让模型自选转场）

风格一致但没有具体转场要求时，给一个受限菜单，比沉默或硬指定都好：
```
每个切点从遮罩、相似物、动作、材质蔓延中选择最适合本片的一种。
```
沉默会得到随机转场；硬指定可能跟素材打架；菜单把选择限制在你认可的集合里。

## 四、编辑已有视频（四件套）

> 源视频是权威，提示词的任务是精确说明**什么变、什么绝不能变**。

```
[编辑目标]
编辑 @video1。在<整段 | 某个时间范围>内，<添加 | 移除 | 替换 | 调整><物体/区域/音频类别>。
[源视频角色]
@video1 是唯一编辑母版，定义人物、场景、动作、构图、运镜、遮挡关系、音频、事件顺序。
[目标素材角色]
@image1 定义<目标物体的指定属性>。不要用<它的背景、构图或无关物体>。
[编辑范围]
只修改<……>。
[需要保留]
保留 @video1 的<绝不能变的全部内容>。
```

四个关键点：

1. **唯一编辑母版**要写出来——不写，参考图会跟源视频争夺构图与调度控制权。
2. **范围写两遍**（改什么+保留什么）——第二半不是冗余，是防连带改动。
3. **目标数量**——替换物体写上存在几个：「全片只有一盏白色台灯；只替换原来那盏黄色的」。
4. **时间轴继承**——替换物继承原物做过的一切：「白色台灯继承原台灯的全部出现、灯臂旋转、手部遮挡与离场，包括时机、路径与速度变化」。不写，替换物常外形对但运动方式不对。

**允许自然反应**：范围别收太紧以致像贴上去的（改灯光颜色时允许皮肤跟着环境光变）。
**音频可单独编辑**：台词/语言/音色/音乐/音效各自可寻址，写明改什么、保留什么。

## 五、向前延长（接在源片之后）

先写边界状态，再写新内容：

```
向前延长 @video1。延长段第一帧直接承接 @video1 的最后一帧。保持
<主体姿态与朝向>、<道具位置>、<背景与空间关系>、<机位与构图>、<光照>、<运动方向>的连续性。
然后，<新的动作、事件、运镜或音频>。
全程保持<人物身份与服装>、<关键道具>、<背景布局>、<动作轴线>的连续性。
每个主体保持为同一个连续实体：不许复制或分裂。
```

这正是接缝默认值（自然延续/动作顺畅/禁生硬切断/禁凭空出现）成立的上下文。

## 六、向后延长（接在源片之前）——会出错的那个方向

原因很具体：属于源片**之后**的角色或效果会提前露面；画面到达目标状态后继续变。
解法：**把源片的首帧写成你正在生成这一段的明确末态**。

```
向后延长 @video1。在源视频开始之前，<前面发生的动作或事件>。
延长段最后一帧自然衔接到 @video1 的第一帧：<主体姿态与朝向>、<道具位置与状态>、
<其他主体位置>。匹配 @video1 首帧的<机位与构图>、<光照>、<运动方向>。
<只应在源视频开始之后出现的素材>不得在向后延长段中提前出现。
```

**只写「然后接上源视频」就是那个翻车写法。**

## 七、接龙（动作长于单次请求）

- 在某一段**真正结束**的地方切，不在动作中途切
- 把**真实生成的尾帧**往前喂——不是设想的尾帧
- 接龙段落**按顺序**生成（互相依赖）；被切点分开的镜头独立生成、剪辑台拼
- 接龙是对齐辅助，**不保证接缝隐形**

## 八、复查边界

边界帧在**视觉上**衔接，不是逐像素拼接——期待像素级完美会导致无限重做。按序检查：①边界两侧（姿态/道具/光/运动方向）②完整延长段（不只接缝）③有没有东西提前出现或错误留存（向后延长）④跨边界音频连续性（延长段音量可能与源片略有差异）。**只重做失败的那一段。**

## 九、本机落地命令（抽帧 · 裁剪 · 拼接）

上面所有的「截取尾帧」「掐头去尾」「拼接成集」在本地用 ffmpeg 完成（全部命令经 30fps 测试片实测，含中文/空格路径；Windows 在 Git Bash 或 PowerShell 中同样可用，含空格路径加引号）。抽帧与拼接对合成长度不敏感，直接用；裁剪分快/准两档，按精度要求选。

**抽帧（接力与衔接用）**：

```bash
# 抽尾帧（作下一镜首帧参考）
ffmpeg -sseof -0.1 -i 镜01.mp4 -frames:v 1 -update 1 镜01_尾帧.png
# 抽首帧（检查构图/作首帧素材）
ffmpeg -i 镜01.mp4 -frames:v 1 -update 1 镜01_首帧.png
```

尾帧抽的是「最后 0.1 秒内的帧」——模型生成的片子常在末帧糊，抽帧后目检一次，糊了就往前多抽几帧挑一张。

**裁剪（跳帧修复：去尾数帧 + 去头 1 帧）**：

快档（`-c copy` 不重编码，秒出，精度受关键帧边界限制、误差 <0.1s，粗修够用）：

```bash
# 去尾 0.2s（先查时长：ffprobe -v error -show_entries format=duration -of csv=p=0 镜01.mp4）
ffmpeg -i 镜01.mp4 -t 4.8 -c copy 镜01_cut.mp4
# 去头 1 帧（30fps 约 0.033s；25fps 用 0.04，60fps 用 0.017）
ffmpeg -ss 0.033 -i 镜02.mp4 -c copy 镜02_cut.mp4
```

准档（trim 滤镜重编码，**帧精确**，适合接缝要求高时；`-an` 丢原声、成片声音走后期轨）：

```bash
# 去头 1 帧
ffmpeg -i 镜02.mp4 -vf "trim=start_frame=1,setpts=PTS-STARTPTS" -c:v libx264 -crf 18 -pix_fmt yuv420p -an 镜02_precise.mp4
# 去尾（保留前 23 帧 → end_frame=23）
ffmpeg -i 镜01.mp4 -vf "trim=end_frame=23,setpts=PTS-STARTPTS" -c:v libx264 -crf 18 -pix_fmt yuv420p -an 镜01_precise.mp4
# 数帧核验（确认裁对了）
ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames -of csv=p=0 镜01_precise.mp4
```

实测参考（30fps 1s 测试片）：copy 去尾 0.2s 实得 0.867s（偏差约 2 帧，属关键帧边界近似）；trim 去 1 帧实得 29 帧、保留 23 帧实得 23 帧，逐帧精确。

**拼接（成集/成片）**：

```bash
# list.txt 每行一个文件（同一批生成参数一致时才能 -c copy 无损拼接）
printf "file '镜01_cut.mp4'\nfile '镜02_cut.mp4'\n" > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c copy 成片.mp4
```

某段参数不同（分辨率/帧率不一致）时 `-c copy` 会拼接失败或花屏，该段单独重编码统一参数后再拼。拼接后建议抽尾帧核验实际结尾，并核对总时长。
